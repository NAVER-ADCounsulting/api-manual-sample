SA API 与 GFA API 的差异

搜索广告（SA）API与效果型展示广告（GFA）API在认证模型、权限发放、结构上各不相同。以两份官方文档为准梳理其差异。

2 核心差异 ① 认证模型

SA采用基于KEY+SECRET的直接签名（HMAC）方式，GFA采用Naver登录OAuth令牌方式。由于认证结构本身不同，SA联动代码无法原样复用于GFA。

SA API — HMAC签名头

bash / curl 
curl -X GET "https://api.searchad.naver.com/ncc/campaigns" \
  -H "X-Timestamp: 1712800000000" \
  -H "X-API-KEY: {已发放的API KEY}" \
  -H "X-Customer: {Customer ID}" \
  -H "X-Signature: {HMAC-SHA256签名值}"

GFA API — OAuth访问令牌头

bash / curl 
curl -X GET 'https://openapi.naver.com/v1/ad-api/1.0/adAccounts/456/campaigns' \
  -H 'AccessManagerAccountNo: 123' \
  -H 'Authorization: Bearer {访问令牌}'

3 核心差异 ② 权限发放

  • SA API：广告主在广告系统内直接申请·发放API许可证 → 任何人均可使用
  • GFA API：需通过官方合作伙伴（代理商）提交使用申请 + 需Naver管理员批准的测试版状态 → 需先在 developers.naver.com 注册应用（Client ID）
⚠️ GFA API与SA API不同，并非自助发放，存在权限准入门槛。

4 联动时参考

  • 由于认证模型不同，SA与GFA须各自单独联动（无法复用通用客户端）。
  • SA以X-Customer、GFA以AccessManagerAccountNo指定目标账户。
  • Base URL与结构术语（关键词 vs creative）不同，端点映射时请注意。
