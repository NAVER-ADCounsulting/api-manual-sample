SA API와 GFA API 차이점

검색광고(SA) API와 성과형 디스플레이광고(GFA) API는 인증 모델·권한 발급·구조가 다릅니다. 두 공식 문서를 기준으로 차이를 정리합니다.

2 핵심 차이 ① 인증 모델

SA는 KEY+SECRET 기반 직접 서명(HMAC) 방식, GFA는 네이버 로그인 OAuth 토큰 방식입니다. 인증 구조 자체가 달라 SA 연동 코드를 그대로 GFA에 재사용할 수 없습니다.

SA API — HMAC 서명 헤더

bash / curl 
curl -X GET "https://api.searchad.naver.com/ncc/campaigns" \
  -H "X-Timestamp: 1712800000000" \
  -H "X-API-KEY: {발급받은 API KEY}" \
  -H "X-Customer: {Customer ID}" \
  -H "X-Signature: {HMAC-SHA256 서명값}"

GFA API — OAuth 액세스 토큰 헤더

bash / curl 
curl -X GET 'https://openapi.naver.com/v1/ad-api/1.0/adAccounts/456/campaigns' \
  -H 'AccessManagerAccountNo: 123' \
  -H 'Authorization: Bearer {액세스 토큰}'

3 핵심 차이 ② 권한 발급

  • SA API: 광고주가 광고시스템 내에서 API 라이선스를 직접 신청·발급 → 누구나 사용 가능
  • GFA API: 공식 파트너(대행사)를 통해 사용 신청 + 네이버 관리자 승인이 필요한 베타 상태 → developers.naver.com 앱 등록(Client ID) 선행
⚠️ GFA API는 SA API와 달리 셀프 발급이 아니며, 권한 진입장벽이 있습니다.

4 연동 시 참고

  • 인증 모델이 다르므로 SA·GFA는 각각 별도로 연동해야 합니다 (공통 클라이언트 재사용 불가).
  • SA는 X-Customer로, GFA는 AccessManagerAccountNo로 대상 계정을 지정합니다.
  • Base URL·구조 용어(키워드 vs creative)가 다르니 엔드포인트 매핑에 유의하세요.
