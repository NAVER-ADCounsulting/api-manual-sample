Differences Between SA API and GFA API

The Search Ads (SA) API and the Performance Display Ads (GFA) API differ in authentication model, access provisioning, and structure. We summarize the differences based on the two official documents.

2 Key Difference ① Authentication Model

SA uses a KEY+SECRET-based direct signature (HMAC) method, while GFA uses a Naver Login OAuth token method. Because the authentication structures themselves differ, you cannot reuse SA integration code as-is for GFA.

SA API — HMAC Signature Headers

bash / curl 
curl -X GET "https://api.searchad.naver.com/ncc/campaigns" \
  -H "X-Timestamp: 1712800000000" \
  -H "X-API-KEY: {issued API KEY}" \
  -H "X-Customer: {Customer ID}" \
  -H "X-Signature: {HMAC-SHA256 signature value}"

GFA API — OAuth Access Token Headers

bash / curl 
curl -X GET 'https://openapi.naver.com/v1/ad-api/1.0/adAccounts/456/campaigns' \
  -H 'AccessManagerAccountNo: 123' \
  -H 'Authorization: Bearer {access token}'

3 Key Difference ② Access Provisioning

  • SA API: The advertiser applies for and issues the API license directly within the ad system → anyone can use it
  • GFA API: A beta state requiring a usage application through an official partner (agency) plus Naver administrator approval → preceded by developers.naver.com app registration (Client ID)
⚠️ Unlike the SA API, the GFA API is not self-issued and has a barrier to access.

4 Integration Notes

  • Because the authentication models differ, SA and GFA must each be integrated separately (a shared client cannot be reused).
  • SA specifies the target account with X-Customer, while GFA uses AccessManagerAccountNo.
  • The Base URL and structure terminology (keyword vs. creative) differ, so take care with endpoint mapping.
